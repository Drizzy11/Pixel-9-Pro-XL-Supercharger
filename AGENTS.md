# Supercharger contributor instructions

Pixel 9 Series Supercharger is a systemless Android root module for Tensor G4.
Read `README.md` and `CONTRIBUTING.md` before changing behavior.

## Boundaries

- Module scripts target `/system/bin/sh`; retain POSIX shell patterns.
- Never execute the installer, service, controller or uninstaller on the host.
- Preserve best-effort writes, device checks, thermal safety and Thermal Control's
  off-by-default installation. Do not force stable-profile clocks, bypass thermal
  limits or override charging behavior.
- Changes to tuning need real-device evidence; host checks do not establish it.
- Do not bump versions or edit `changelog.md` during routine maintenance.
- Keep text LF. Release ZIPs use the allowlist in `.github/workflows/release.yml`;
  never package docs, website files, tests, logs or runtime state.

## Layout and checks

- `customize.sh`, `service.sh`, `uninstall.sh`, `bin/supercharger_ctl.sh`: module
  lifecycle and commands. See `CONTRIBUTING.md` for module checks.
- `webroot/`: Android WebUI, plain HTML and ES modules. Run
  `node --test scripts/webui_regression.test.mjs` for its regressions.
- `thermal_profiles/`: bundled opt-in overlays.
- `scripts/validate_release.py`: `python3 scripts/validate_release.py --profile main --source .`.
- `site/`: public English/Spanish website. It has no Android bridge or backend.
  `site/index.html` is the English landing-page source; the other HTML pages are
  generated by `scripts/build_site.py`. See `docs/WEBSITE.md` before editing them.

For the website, use Python 3.10+ and Node 24:

```sh
python3 scripts/build_site.py
python3 scripts/check_site.py
python3 scripts/serve_site.py
```

The offline website gate checks links, languages, JS syntax, interactions,
requirements, ZIP hashing, issue drafts, release data and atomic rendering.
Also verify changed flows in a browser on desktop and mobile. Keep metadata
strictly public; never expose draft releases. The report builder only prepares
a user-reviewed GitHub form, and ZIP verification runs locally in the browser.

Use Conventional Commit subjects. Keep usage in README, development commands in
CONTRIBUTING and website architecture in `docs/WEBSITE.md`.
